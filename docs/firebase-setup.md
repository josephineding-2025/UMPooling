# Firebase Analytics setup

The root Gradle build declares Google services plugin 4.6.0 without applying it.
The app module applies the plugin and imports Firebase BoM 35.2.0 plus the
versionless `firebase-analytics` dependency. The BoM selects compatible Firebase
SDK versions. Supabase remains the app's authentication and database backend.

## Configure your local Android project

1. Register an Android app in the intended Firebase project with package name
   **com.fopgang.umpooling** (the app's namespace and application ID).
2. Download its `google-services.json` from Firebase Console and place it at
   `app/google-services.json`. The JSON's Android client package must match the
   application ID. Do not commit this file: `.gitignore` and CONTRIBUTING.md
   require it to remain local. Teammates and CI need their own copy supplied
   through the team's private configuration process.
3. In Android Studio, select **Sync Project with Gradle Files**. Use JDK 21 and
   install the team's Android SDK 36.1.
4. Build and run the app. Firebase initializes through its SDK provider using
   the resources generated by the Google services plugin; no manual Application
   initialization is needed for this default setup.
5. Enable Firebase Analytics DebugView for a connected development device:

   ```sh
   adb shell setprop debug.firebase.analytics.app com.fopgang.umpooling
   ```

   Open the app and check Firebase Console > Analytics > DebugView for events.
   Disable debug mode afterward:

   ```sh
   adb shell setprop debug.firebase.analytics.app .none.
   ```

## Verification status

The requested plugin and BoM versions were verified in Google's Maven repository.
The BoM includes Firebase Analytics (24.0.0). Static checks verified the Gradle
entries, package name, and ignore rule. No google-services.json was supplied to
this environment, so Firebase configuration and event delivery are unverified.
Build/unit test execution is also blocked by the environment's Gradle distribution
download failing with a connection-refused error. A normal build requires the
real local JSON; the Google services task will fail if it is missing or does not
contain a matching Android client. Complete steps above before merging.
